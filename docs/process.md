# Process rules

Rules for anything process-shaped. `project.yml` points every
`**Process**` bullet in a roadmap item at this file.

Each rule is one imperative and one line of why. A rule with no why is a
preference, and the next person will not know whether to keep it.

Numbered, because roadmap items cite them by number — renumbering breaks the
citations, so append rather than reorder.

1. **Build one vertical slice end to end before widening any layer.** One hunt,
   one monster, one skill, no items, ugly rendering — but including the server,
   the save, the offline replay and the login, because a pipeline that has never
   run end to end is a pipeline with unknown gaps.

2. **Play it yourself for a week before anyone else sees it.** Testers are a
   one-shot attention resource, and the first boring version should cost your
   time rather than theirs.

3. **State the alpha's exit criteria as one sentence before starting it.**
   Without a stated bar an alpha expands forever, because there is always one
   more system.

4. **Record every third-party asset's licence and required attribution when you
   download it.** Reconstructing where a sprite set came from a year later is
   miserable, and most open-source art licences want credit in a specific form.

5. **Decide and announce the save-wipe policy before testers have characters.**
   Losing a character to an undocumented breaking change costs a tester, not
   just a save file.
